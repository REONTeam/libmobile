Scope, firmware inputs, and evidence

The protocol suite tests game-visible 8-bit exchanges, not a complete adapter emulator. Original firmware runs from seeded RAM, without executing its reset/boot path. It executes its serial parser, command dispatch, validation, response framing, and UDP connection bookkeeping. EEPROM driver operations, phone status/disconnect, and low-level socket calls are controlled substitutes. Physical serial timing, the original TCP/IP stack, and a real network are not exercised. Timer events are frozen: pending tests check that polling alone does not complete a request, not its physical duration. The separate AT diagnostics execute the original command-body parser and handlers without firmware function substitutions. They inspect flags, settings, and cursor progress at an internal boundary, not game-visible response bytes or the complete phone transport. libmobile has no corresponding internal AT parser, so these cases are not run against the library. The DDI candidate target flips one bit in a private ROM copy at file offset 0xC3D0 (5EFF to 7EFF). Original-image results remain separate. The 10,000-instruction ceiling detects nonreturning cases; it is not a latency measurement. This repair is strongly supported, but the cause of the defective byte and the integrity of the whole dump remain unproven. The supplied Ghidra archive contains exactly the same bytes as these two dumps. Passing both images corroborates these selected paths, not the entire dump. Library-only runs use the recorded firmware contracts without requiring ROMs. A FAIL is a contract difference, including intentional extensions and firmware quirks; an ERROR is a harness/runtime problem. Neither is silently marked PASS.
